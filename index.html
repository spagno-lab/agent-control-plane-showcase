01 / The problem

Prompts start work.
They do not govern it.

Autonomous execution needs more than a clever model. It needs durable intent, explicit ownership, bounded retries, live feedback, and an independent answer to one hard question: did the world actually change?

Prompt loop

Ephemeral instructions, implicit state, success reported by the worker.

Control loop

Versioned intent, observed state, recoverable work, success verified externally.

Tested admission safety

References are authority, not hints.

A worker must resolve the requested Job in the canonical queue before it acts. When a requested reference was absent, execution failed closed: no invented scope, no inferred approval, and zero external mutation. A versioned Goal and bounded Job were created before work resumed.

04 / Target end-to-end flow

One command. Two explicit loops.

A

Machine reconcile loop

  1. Read desired state
  2. Observe authoritative reality
  3. Compare and create minimal work
  4. Dispatch to an eligible worker
  5. Re-observe after completion
  6. Set Ready only when verified
B

Human intent loop

  1. Review the converged outcome
  2. Apply qualitative judgment
  3. Refine success criteria or constraints
  4. Increment Goal generation
  5. Preserve prior Jobs as history
  6. Reconcile only the delta

Append-only correction

A wrong conclusion is corrected, not erased.

During one verification Job a privileged access attempt failed and was reported as unusable credentials. The credentials were valid; the attempt had used the wrong account. The Job still converged, because independent APIs, bounded logs, network probes and workload state satisfied the evidence bar without that access path.

The original record stays intact and a later correction is appended on top of it. Misclassifying a working credential is itself a defect, so the audit trail must show the failed attempt, the reason it failed, and the corrected conclusion.

07 / Safety boundary

Autonomy with
hard edges.

01

Least authority

Workers receive only the capabilities required for their bounded Job.

02

Leased ownership

Claim tokens and expiry prevent stale workers from mutating shared state.

03

Privileged enrollment

Anonymous enrollment is Worker-only; Orchestrators require explicit, bounded authorization.

04

Publication boundary

Public material is a sanitized projection—not a mirror of operational systems.

05

Separate context authority

Memory Service owns durable semantic context, never claims, leases, retries, or credentials for ACP.

06

Repository discipline

One writer per repository and isolated branches are current operating policy; ACP does not yet enforce a repository mutation lease.

08 / Roadmap

From execution authority to convergence.

The runtime protocol remains deployment-neutral; Kubernetes is an optional projection, not the authority model.

Now

Runtime authority

Goals, Jobs, Workers, Runs, atomic claims, leases, fencing, retries, events, enrollment, and polling dispatch.

Next

Goal reconciliation

Independent observation, generation handling, deterministic Ready conditions, and durable controller leadership.

Then

Runtime feedback

Low-latency structured status, artifacts, cancellation, and bounded adapter authority.

Optional

Kubernetes projection

Portable protocol concepts represented as Kubernetes resources without making Kubernetes the source of truth.
